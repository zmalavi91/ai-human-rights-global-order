# Algorithmic Accountability Checklist

## Governance

- [ ] Is there a clearly identified responsible institution?
- [ ] Is responsibility assigned to named officials or departments?
- [ ] Is there an independent oversight mechanism?
- [ ] Is the system included in an institutional risk register?
- [ ] Are procurement and vendor responsibilities documented?

## Purpose

- [ ] Is the purpose specific and legitimate?
- [ ] Is the use necessary?
- [ ] Were less intrusive alternatives considered?
- [ ] Is the system being used only for the approved purpose?
- [ ] Is function creep monitored?

## Data

- [ ] Are the data lawfully collected?
- [ ] Are the data accurate?
- [ ] Are the data representative?
- [ ] Are sensitive data protected?
- [ ] Is data minimization applied?
- [ ] Are retention limits established?
- [ ] Are deletion procedures available?

## Equality

- [ ] Has bias testing been conducted?
- [ ] Have error rates been compared across groups?
- [ ] Have gender, caste, race, disability, language, and class impacts been examined?
- [ ] Are discriminatory outcomes investigated?
- [ ] Are mitigation measures documented?

## Transparency

- [ ] Are affected persons informed?
- [ ] Is the system’s purpose publicly available?
- [ ] Are decision criteria explained?
- [ ] Are system limitations disclosed?
- [ ] Are audit results published where appropriate?

## Human Oversight

- [ ] Is meaningful human review available?
- [ ] Are reviewers trained?
- [ ] Can officials override the system?
- [ ] Are overrides recorded?
- [ ] Is automated output treated as advisory or determinative?

## Accountability

- [ ] Is someone legally responsible for harm?
- [ ] Are incidents documented?
- [ ] Are independent audits conducted?
- [ ] Are vendors accountable?
- [ ] Are sanctions or corrective measures available?

## Remedy

- [ ] Can affected persons challenge decisions?
- [ ] Can inaccurate data be corrected?
- [ ] Is an appeal process available?
- [ ] Is judicial or independent review available?
- [ ] Are remedies accessible to vulnerable groups?

## Security

- [ ] Are systems protected against unauthorized access?
- [ ] Are data breaches reported?
- [ ] Are cybersecurity risks regularly assessed?
- [ ] Are third-party access arrangements monitored?
- [ ] Is sensitive data encrypted where appropriate?

## Participation

- [ ] Were affected communities consulted?
- [ ] Were civil-society organizations involved?
- [ ] Were human-rights experts consulted?
- [ ] Were disability and language-access needs considered?
- [ ] Is public feedback incorporated?

## Environmental Responsibility

- [ ] Has energy consumption been assessed?
- [ ] Have environmental costs been documented?
- [ ] Are sustainability measures available?
- [ ] Are environmental impacts disproportionately experienced by vulnerable communities?

## Final Assessment

- [ ] The system is adequately governed.
- [ ] The system requires additional safeguards.
- [ ] The system requires independent review.
- [ ] The system should be suspended.
- [ ] The system should not be deployed.
